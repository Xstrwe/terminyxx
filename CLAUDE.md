# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Terminyxx is a cross-platform (Windows + macOS) desktop SSH terminal, SFTP file manager and RDP client built with **Wails v2** (Go backend) and a **React 19 + TypeScript + Tailwind + xterm.js** frontend. `DEVELOPMENT_PLAN.md` (in Russian) tracks the phases. **All UI text must be in English.**

## Commands

Run from the repo root unless noted:

- `wails dev`: live development (Vite HMR for the frontend, Go rebuild on change). A browser dev server with Go bindings is also exposed at http://localhost:34115.
- `wails build`: production build; output goes to `build/bin/`.
- Release: bump `info.productVersion` in `wails.json`, then push a tag `vX.Y.Z`. `.github/workflows/release.yml` builds on windows-latest, stamps the tag's version into `wails.json`, packages `build/windows/installer/terminyxx.iss` with Inno Setup, and publishes the setup, a portable exe and `SHA256SUMS.txt` as a GitHub release (a `-suffix` tag becomes a prerelease). `ci.yml` runs the frontend build, `go vet` and `go test` on pushes to main and on PRs. Local installer: `iscc /DAppVersion=X.Y.Z build\windows\installer\terminyxx.iss` (from Git Bash set `MSYS_NO_PATHCONV=1`).
- `wails generate module`: regenerate the TS bindings in `frontend/wailsjs/` after changing exported `App` methods or bound structs (`wails dev`/`wails build` also regenerate them).
- `cd frontend && npm run build` (or `npx tsc --noEmit`): the only typecheck; there is no linter configured.
- `go build ./...` / `go vet ./...`: `main.go` embeds `frontend/dist` via `//go:embed all:frontend/dist`, so the frontend must be built at least once before plain `go build` succeeds.
- `go test ./internal/...`; a single test: `go test ./internal/connection -run TestSFTPRoundTrip`. The connection tests start an in-process SSH server (`server_test.go`: password, keyboard-interactive and public-key auth, a fake shell, and an in-memory SFTP server) and an in-process ssh-agent, so no external server is needed. Store tests use `MemorySecrets` instead of the OS keychain. `-race` needs CGO, which is off on this machine.
- `TERMINYXX_DATA_DIR=<dir>` puts the database and `known_hosts` in `<dir>` instead of `os.UserConfigDir()/terminyxx`. Use it to try things without touching real data (`.claude/launch.json` has a `wails-dev-sandbox` config). Passwords still go to the real OS keychain, so delete test hosts through the app afterwards.

## Architecture

```
React UI state  ──Wails bindings (calls)──▶  App (app.go)  ──▶  internal/connection, store, rdp
xterm.js        ◀──Wails events (stream)───  PTY / SFTP goroutines (via EventEmitter)
```

- **`app.go`** is the only bound struct; every method on `App` is exposed to the frontend as `frontend/wailsjs/go/main/App.{js,d.ts}`, with Go structs mirrored in `wailsjs/go/models.ts`. Those files are generated, so don't hand-edit them. Store bindings no-op (return empty or nil) when `store.New()` failed at startup.
- **`internal/connection`**: `ConnectionManager` maps connection IDs to `ManagedConnection`s. The **frontend generates the ID** (the tab's `crypto.randomUUID()`). One `*ssh.Client` per tab carries both the PTY and a lazily created SFTP client (`SFTP()`), so SFTP never opens a second TCP connection. The package talks to Wails only through the `EventEmitter` interface, so tests run without Wails.
  - **Connection lifecycle**: `Connect` dials without holding the manager lock and does **not** start a shell. The terminal subscribes to output first and then calls `SSHStartShell(id, cols, rows)`, so the login banner is never lost; a repeat call only resizes, which keeps React StrictMode remounts safe. Every way a connection can end (shell `exit`, network drop, keepalive timeout) goes through `client.Wait()` → `handleClosed`, which emits `connection:state:{id}` = `disconnected` only if the connection is still the current one for that ID.
  - **Errors the UI must react to** come back as strings with a machine-readable prefix, parsed in `frontend/src/lib/connect.ts`: `HOSTKEY_UNKNOWN|host|type|fingerprint` (the user confirms, and the retry passes `acceptHostKey`), `HOSTKEY_MISMATCH|…` (a hard error), and `KEY_PASSPHRASE_REQUIRED|path`.
  - **Host keys** (`hostkeys.go`): new keys are written to the app's own `os.UserConfigDir()/terminyxx/known_hosts`. `~/.ssh/known_hosts` is read but never written. `HostKeyAlgorithms` is limited to the key types already known for a host, so a host that is already trusted isn't reported as a mismatch.
  - **PTY output** (`pty.go`) is forwarded in chunks that never split a multi-byte UTF-8 character (`streamUTF8`/`incompleteTail`), because Wails events are JSON strings and a split character would be garbled.
  - **Transfers** (`transfer.go`): `SFTPTransfer(id, {jobId, direction, sources, destDir, move})` copies files and folders recursively using pkg/sftp's concurrent `ReadFromWithConcurrency`/`WriteTo`. Progress events are throttled (`sftp:progress:{id}`, filtered by `jobId`), and `SFTPCancelTransfer(jobId)` cancels through a context.
- **Events**: `terminal:output:{id}`, `terminal:closed:{id}`, `connection:state:{id}` (`connecting`/`connected`/`disconnected`), `sftp:progress:{id}`. The frontend subscribes with `EventsOn` from `wailsjs/runtime`.
- **`internal/rdp`**: launches the OS's native RDP client. Platform code is split by build tags (`launcher_windows.go` writes a `.rdp` file and runs `mstsc.exe`, `launcher_darwin.go`, and `launcher_other.go`, which returns unsupported); keep all three building.
- **`internal/capture`**: hides the window from screen capture/sharing (`SetCaptureProtection` binding). Windows uses `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` on every top-level window of the process (falls back to `WDA_MONITOR`), macOS sets `NSWindow.sharingType = NSWindowSharingNone` on the main thread; other OSes return `ErrUnsupported`. The frontend (`lib/captureProtection.ts`) applies `settings.security.hideFromCapture` (default on) at startup and on change; `StatusBar` shows a notice only while screen sharing is detected (`showCaptureNotice`). Detection (`sharing_windows.go`) runs every 2s from `App.watchScreenSharing` and emits `capture:sharing`: Windows 11 records active `Windows.Graphics.Capture` users under `HKCU\…\CapabilityAccessManager\ConsentStore\graphicsCapture*` (`LastUsedTimeStop == 0`, exe still running), Zoom runs `CptHost.exe` only while sharing, and recorders that use DXGI Desktop Duplication (OBS, Streamlabs, XSplit, Camtasia) leave no record, so they count as capturing while their process runs (`helperProcs` in `sharing.go`). macOS can't detect sharing, so there the notice is always shown.
- **Security** (`internal/security`, `app_security.go`, `components/security/`, Settings → Security):
  - **Settings**: `security.SecurityConfig` mirrors `AppSettings.security` in `lib/settings.ts`. It lives in the one settings JSON blob; `SaveSettings` decodes it (`FromSettingsJSON`) and pushes a `connection.Policy` to the manager, and `updateSettings` saves security changes immediately instead of debouncing.
  - **App lock**: the master password is an Argon2id hash under its own settings key `lock.hash` (never in the JSON). `security.Lock` throttles guesses; with a password set the app starts locked. While locked, `ConnectionManager.SetLocked` makes the `OutputGate` queue PTY events (8 MiB per connection, then the reader blocks and SSH flow control pauses the server) and refuses input; the UI is blurred and `inert` under `LockScreen`. `main.tsx` awaits `initAppLock()` before the first render. Inactivity is timed in `lib/appLock.ts`; minimize/sleep in `App.watchLockTriggers`. Biometrics: Windows Hello through raw WinRT COM (`IUserConsentVerifierInterop`, no CGO; the `IAsyncOperation` IID is computed from its type signature), Touch ID through cgo `LocalAuthentication`. Shortcut Ctrl+Shift+L (Cmd+L on macOS); plain Ctrl+L stays with the shell.
  - **Output masking** (`connection/masking.go`): per-PTY `OutputMasker` between `streamUTF8` and the gate. It masks only printable text (escape sequences pass through), keeps width (one `•` per character), uses the already-emitted line as context so split chunks still match, and briefly holds back a trailing word that could start a self-identifying token. Ctrl+Shift+M or the status bar toggles it.
  - **Host keys**: mismatch errors carry the trusted keys (`HOSTKEY_MISMATCH|host|type|fp|type fp;…`); replacing requires `acceptHostKey` + `replaceHostKey` and only rewrites the app's own `known_hosts` (`trusted_hosts.go`, also behind the Trusted hosts manager).
  - **Algorithms / agent** (`connection/policy.go`): "modern only" uses `ssh.SupportedAlgorithms()` minus SHA-1; a host can allow legacy ones (`allow_legacy_algorithms`, migration v4; the error prefix `LEGACY_ALGORITHMS_REQUIRED|` lets the connect flow offer it). Agent forwarding needs both the global switch and the host's `agent_forwarding`.
  - **Clipboard**: every copy goes through `lib/clipboard.ts` → `ClipboardWrite`, which schedules `ClipboardGuard` to clear it only if its SHA-256 still matches. Paste protection (`lib/pasteGuard.ts`) and the OSC 52 policy are enforced in `XTermWrapper`; OSC 8 links open only http(s) after a confirm.
  - **WebView**: production builds send a strict CSP header (`csp.go`, not under `wails dev`) and a matching `<meta>` (Vite plugin). Never ship `wails build -devtools`.
- **`internal/store`**: SQLite via `modernc.org/sqlite` (pure Go, no CGO).
  - **Migrations**: `migrations[i]` upgrades `PRAGMA user_version` i → i+1. Append a new entry and never edit a released one. v1 is the original schema, written with `IF NOT EXISTS` so databases from before versioning upgrade cleanly.
  - **Passwords** live in the OS keychain (`secrets.go`, `go-keyring`: Windows Credential Manager or macOS Keychain, service `terminyxx`, key `ssh:<id>`), not in SQLite.
    - `SSHProfile.Password` is write-only: lists return it empty with `hasPassword`, an empty password on save keeps the stored one, and `clearPassword` deletes it.
    - At connect time `SSHConnect` resolves the password from the keychain using `ConnectRequest.profileId`, so the frontend never holds saved passwords.
    - If the keychain is unavailable, the DB column is the fallback. Startup moves legacy plaintext passwords into the keychain.
  - **Folders**: a `folders` table (`parent_id`, `color`, `sort_order`) plus `folder_id` and `sort_order` on `ssh_profiles` and `rdp_profiles`. `MoveItem(kind, id, parentId, index)` renumbers siblings. Folders and hosts are ordered separately, SSH and RDP hosts share one order, and moves that would create a folder cycle are rejected. `DeleteFolder` moves the folder's contents up a level.
- **`internal/importers`**: the "Import from another app" backend. Each source is one file that calls `register(source{...})` in `init()`:
  - Sources: OpenSSH config, MobaXterm, PuTTY, KiTTY, WinSCP, SecureCRT, Tabby, Termius (CSV), FileZilla, `.rdp` files.
  - Each source has `detect()`, which finds its data on this machine (a file path, or `"Registry: HKCU\…"` for registry-based clients), and `read(paths)`. `Pick` (`file` | `files` | `folder`) controls which dialog `PickImportPaths` opens, so exports copied from another OS work too (e.g. a PuTTY `.reg` export on macOS).
  - Everything is mapped to the common `Host` type, and unsupported session types (Telnet, FTP, …) are counted in `Skipped`.
  - `readText` handles UTF-8/UTF-16 BOMs (regedit and mstsc write UTF-16) and falls back to the ANSI code page. Registry access is in `platform_windows.go`, with a stub elsewhere.
  - Bindings: `ListImportSources`, `ReadImport(id, paths)` (empty = detected data), `PickImportPaths(id)`.
  - To add a source: a new file with a parser plus a test in `importers_test.go` that uses a synthetic sample of the format.
- **PuTTY `.ppk` keys** (v2/v3, encrypted or not) are loaded in `connection/auth.go` via `github.com/kayrus/putty`. Test vectors are in `connection/testdata/`.
- **`internal/mobaxterm`** (used by the MobaXterm source): reads MobaXterm sessions from an exported `.mxtsessions` file or `MobaXterm.ini`, which it finds through the registry's `LastIniPath`, `%APPDATA%\MobaXterm` or `Documents\MobaXterm`.
  - `[Bookmarks*]` sections each hold a `SubRep` folder path (`\`-separated) and session lines `name=#icon#type%host%port%user%…`. For SSH, field 14 is the key path and fields 7–9 the gateway (jump host).
  - Types 0 (SSH) and 7 (SFTP) import as SSH hosts and 4 as RDP. Other types are counted in `Skipped`.
  - The files are in the Windows ANSI code page (cp1251 on Russian Windows), not UTF-8. `decode()` converts using `GetACP()`.
  - Placeholders such as `_ProfileDir_` are expanded, and a `.pub` key path is mapped to the private key.
  - Passwords are encrypted with MobaXterm's master password and are not imported. The connect flow (`lib/connect.ts`) prompts for missing passwords, offers to save them to the keychain, and re-prompts after an authentication failure.
- **`internal/sshconfig`** (used by the OpenSSH source): parses `~/.ssh/config` (with `Include`, `Host *` defaults, negated patterns, first-value-wins). `ProxyJump` is read but jump hosts aren't implemented yet.
- **Jump hosts and tunnels** (`connection/connection.go`, `tunnel.go`): `ConnectRequest.Jump` is a chain of hops dialed one through the previous (`dialHop`/`dialThrough`); the intermediate clients live in `ManagedConnection.jumps`. `App.SSHConnect` fills `Jump` from the saved profile's `jumpProfileId` (migration v6, `JumpFor` in the request; passwords come from the keychain, loops and depth >5 are rejected). Tunnels (`StartTunnel`/`StopTunnel`/`ListTunnels`) are local (-L), remote (-R) and dynamic (SOCKS5, CONNECT only) forwards owned by one connection and closed with it. Saved tunnels are a JSON column on `ssh_profiles`; those with `autoStart` start after connect. UI: `TunnelEditor` in the host dialog, `TunnelsPopover` in the status bar.
- **Built-in RDP client** (`internal/rdpgw`, `app_rdp.go`, `components/rdp/RdpPane.tsx`, `lib/rdpConnect.tsx`): RDP hosts open in a pane by default (`settings.rdp.builtin`; the sidebar's "Open in system client" and the setting fall back to `LaunchRDP`). The engine is IronRDP compiled to WebAssembly (the `iron-remote-desktop` web component + `-rdp` backend, ~5 MB, lazy-loaded chunk). Both are built from IronRDP source and vendored in `frontend/vendor/ironrdp` (`build.sh`, commit in its README) because the npm releases embed an sspi whose NTLM Windows 11 rejected; rebuild both from the same commit. It can't open sockets, so it talks to `rdpgw.Gateway`, a WebSocket server on `127.0.0.1:<random>`, using IronRDP's RDCleanPath protocol (`pdu.go`, DER, checked against IronRDP's test vectors): the gateway forwards the client's X.224 request, upgrades to TLS, checks the certificate and returns the chain; after that it only relays bytes. The gateway caps TLS at 1.2: Windows' RDP server finishes a TLS 1.3 handshake and then sends `internal_error`, which it logs as a misleading ERROR_LOGON_FAILURE (0x8007052E). `TERMINYXX_RDP_TRACE=1` logs the relayed CredSSP/NTLM messages (`trace.go`: types, flags, user/domain, MIC, the server's `errorCode`; never secrets). CredSSP/NLA runs in the webview, so `RDPOpen` returns the password to the frontend (it's dropped from tab state when the session ends). Certificates: `RDPOpen` probes the server first; a chain that doesn't verify against system roots must match `<data dir>/rdp_known_certs` (TOFU) or the call fails with `RDPCERT_UNKNOWN|…`/`RDPCERT_CHANGED|…` and the retry passes the accepted fingerprint; the gateway checks again after its own handshake. Tickets are single-use, expire after a minute and are bound to one tab and destination; `RDPLastError(tab)` explains gateway-side failures (the client only sees a code). Windows drops the connection on wrong NLA credentials, which `RdpPane` reports as a probable wrong password. On macOS, LAN connects need the Local Network permission (`NSLocalNetworkUsageDescription` in `build/darwin/Info*.plist`); `localNetworkHint` (`localnet.go`) explains `no route to host`. The CSP allows `'wasm-unsafe-eval'` and `connect-src data: ws://127.0.0.1:*` for this. Sound: the `audioPlayback` extension feeds PCM to `lib/rdpAudio.ts` (Web Audio, chunks scheduled back to back) when the profile's audio mode is `local`. High-density screens: the desktop is requested in device pixels with `desktopScaleFactor` (and `resize(w, h, percent)`), so Windows scales its UI like on a Retina display. Full screen: `App.rdpFull` puts the window in full screen and the pane switches to `fixed z-[55]` (above the UI, below dialogs at z-60) without remounting; `FullscreenBar` in `RdpPane` is the mstsc-style connection bar; `Ctrl+Alt+Enter` toggles it, and a window resize that leaves OS full screen ends it. `RdpDialog` hides the options the built-in client can't do while `settings.rdp.builtin` is on (values are kept for the system client). Not done yet: clipboard beyond the component's own, drive/printer redirection, the H.264 graphics pipeline (IronRDP web has it off), gateways, RDP certificates in the Trusted hosts manager.
- **RDP options** (`rdp/types.go`, `launcher.go`): `RDPProfile.Options` (JSON column, migration v5) drives the `.rdp` file; `buildRDPFile` is shared and `windowsOnly` gates keys macOS ignores. The password is kept in the keychain (`rdp:<id>`) and on Windows is written to Credential Manager as `TERMSRV/<host>` at launch.
- **Snippets and typing in all panes**: snippets are rows in the `snippets` table (migration v7, `store/snippets.go`; bindings `ListSnippets`/`SaveSnippet`/`DeleteSnippet`). `lib/snippets.ts` parses `{{name}}` / `{{name:default}}` placeholders (`host` and `user` are filled from the active tab) and types the text into a pane with `SSHWriteInput`. `lib/broadcast.ts` holds the "type in all panes" state: `XTermWrapper`'s `onData` sends input to `inputTargets(id)`, and `App` feeds it the panes of the visible tab (any layout change turns it off). Shortcuts: Ctrl+Shift+S snippets, Ctrl+Shift+G broadcast.
- **Encrypted sync file** (`internal/syncfile`, `store/sync.go`, Settings → Sync): `ExportSync`/`ImportSync` seal a `store.Bundle` (folders, SSH and RDP hosts, snippets, optionally saved passwords) as JSON into one file: Argon2id (t=3, 64 MiB) key, AES-256-GCM, header authenticated, parameters from a file are range-checked. Import merges by ID and never deletes; settings, the lock password and host keys are not included. The UI fires `terminyxx:library-changed` so `App` reloads hosts.
- **Session recording** (`internal/recording`, `connection/pty.go`, `RecordButton`, `RecordingsDialog`): REC in the status bar saves the terminal output of one connection as an asciicast v2 file in `<data dir>/recordings` (0600). The tap is `raw()` in `pty.go`, after masking, so masked secrets stay masked; keyboard input is never recorded; a file stops growing at 256 MiB. `ManagedConnection.rec` is an atomic pointer toggled at runtime, and resizes are logged as `r` events. The library lists, plays (xterm with squeezed idle gaps and seeking), deletes and full-text searches recordings (ANSI stripped, lines re-joined across chunks); names are validated as plain `.cast` file names. Nothing prunes old recordings yet.
- **Host monitor** (`connection/monitor.go`, `layout/HostMonitor.tsx`): the activity button in the status bar polls `HostStats(id)` every 3 s (opt-in, remembered in localStorage). One `ssh` exec session per poll reads `/proc` and `df` (Linux only; other systems give `ErrMonitorUnsupported` and the UI stops polling). CPU and network rates are deltas against the previous call, kept per connection in `monitorState`; the first sample reports -1. It does not run while the app is locked.
- **Remote editor** (`connection/edit.go`, `sftp/RemoteEditor.tsx`, F4 on a server file): plain-text editing over the SFTP client. `ReadForEdit` refuses folders, files over 2 MiB, NUL bytes and invalid UTF-8 (a save would corrupt them) and returns a version (`mtime:size`). `WriteEdited` rejects a changed file with `EDIT_CONFLICT|…` unless `force`, follows symlinks, writes a hidden temp file in the same folder and renames it over the original with the old permissions (falls back to overwriting in place when the folder is read-only). The editor keeps CRLF files CRLF, asks before discarding changes, and Ctrl+S saves. There is no syntax highlighting.
- **Telnet and serial** (`connection/stream.go`, `telnet.go`, `output.go`; `go.bug.st/serial`): `StreamConnect` opens a raw stream kept in `ConnectionManager.streams` (not `connections`), so it has no SFTP, tunnels, monitor or containers; every other manager method (`StartShell`, `WriteInput`, `ResizePTY`, `Disconnect`, recording) checks `streams` first and the UI sees the same `terminal:output`/`connection:state` events. Output goes through the shared `outputPipe` (recording, masking, lock gate). `telnetConn` strips IAC commands, accepts only SGA, remote ECHO, NAWS and TTYPE (refuses the rest), doubles 0xFF and sends CR as CR NUL. Telnet and serial tabs are quick connections (`TerminalTab.stream`, `StreamDialog`); there are no saved profiles for them yet.
- **Containers** (`connection/containers.go`, `ContainersDialog`): `ListContainers(id, docker|podman|kubectl)` runs `ps`/`get pods` over an exec channel; names are matched against a strict allow-list before they go into the `exec -it` command that is typed into a new pane (`lib/initialInput.ts` holds text to write once that pane's shell has started). The new pane is a second SSH connection to the same saved host.
- **SFTP-only hosts** (`SSHProfile.SFTPOnly`, migration v8, "SFTP only" toggle in `ConnectDialog`): the session is still one `ssh.Client`, but `App.tsx` renders `SftpPanel fill` as the whole pane and never mounts `XTermWrapper`, so `SSHStartShell` is never called (servers with `ForceCommand internal-sftp` or a nologin shell would reject it). Terminal-only status bar items, the bottom SFTP drawer and the Containers action are hidden for such tabs. Sidebar rows show an SSH/SFTP/RDP badge (`sidebar/ProtoBadge.tsx`). Importers don't set `sftpOnly` yet (MobaXterm type 7 still imports as plain SSH).
- **Key auth** (`connection/auth.go`, `agent.go`): an explicit key file comes first, then ssh-agent. Without an explicit key it tries ssh-agent, then the default `~/.ssh/id_*` keys. The agent is `$SSH_AUTH_SOCK`, or on Windows the OpenSSH agent named pipe.
- **Frontend**:
  - `App.tsx` owns all top-level state. A tab's `status` is `idle | connecting | connected | disconnected`; `started` keeps the xterm mounted after a disconnect so a reconnect can reuse it.
  - **Split panes**: a session (`TerminalTab`, one SSH connection) is a pane. The title-bar tabs are `groups: TabGroup[]` (`lib/layout.ts`), each a tree of row/column splits with pane ids as leaves and fractional `sizes`. `activeTabId` is the focused pane, and its group is the visible tab. `SplitView.tsx` renders **every** session as one flat, absolutely positioned list and only computes rects from the active group's tree, so changing the layout never remounts an xterm (which would lose scrollback). Drag and drop (title-bar tabs and chips, pane headers, sidebar SSH hosts) goes through `lib/paneDrag.ts`, because `dragover` can't read `dataTransfer`. Shortcuts: Ctrl+Shift+D/E split right/down (this reconnects to the same host), Alt+arrows move focus but are bound only while the tab is split.
  - **Settings** (`lib/settings.ts`, `components/settings/SettingsDialog.tsx`, gear button in `TitleBar`, Ctrl+,): one JSON blob in the SQLite `settings` table (`GetSettings`/`SaveSettings`), loaded in `main.tsx` before the first render; `normalize()` fills in missing fields. Components read it with `useSettings()`; `XTermWrapper` subscribes and updates open terminals live. Terminal themes are in `lib/themes.ts`. Keyword highlighting (`lib/highlight.ts`, `OutputHighlighter`) rewrites the output stream with SGR codes, only for text in the default foreground color and never on the alternate screen; highlight colors are ANSI names so they follow the theme.
  - Native `alert`/`confirm`/`prompt` don't work in every Wails webview (macOS WKWebView ignores them). Use `useDialogs()` from `components/ui/Dialogs.tsx` instead: promise-based `confirm`, `prompt` and `toast`. It returns focus to the previously focused element when a dialog closes.
  - Layout: `TitleBar` (custom chrome with inline tabs; the window is frameless on Windows with its own min/max/close buttons, and uses an inset title bar on macOS that leaves 80px for the traffic lights; drag regions use the `.drag` and `.no-drag` classes), `components/sidebar/` (a resizable tree that snaps to a 56px icon rail below 150px, where folders open as flyouts; drag-and-drop in `HostTree.tsx`; all host and folder actions and context menus in `useHostLibrary.tsx`), the terminal card, the SFTP drawer, `StatusBar`, and `Welcome` when no tab is open. `CommandPalette` lists hosts, tabs and actions, and quick-connects when the input parses as `user@host:port` (`parseQuickTarget` in `lib/hosts.ts`).
  - Styling: colors are CSS variables in `style.css` (`--app`, `--surface`, `--raised`, `--accent`, ...) mapped in `tailwind.config.js`, where Tailwind `gray` is remapped to `zinc`. Inter and JetBrains Mono are bundled through `@fontsource-variable`, so the app needs no network for fonts. The terminal theme (`TERMINAL_THEME` in `XTermWrapper.tsx`) matches `--surface`.
  - Hotkeys (`hooks/useHotkeys.ts`) match on `e.code`, not `e.key`, so they work with non-Latin keyboard layouts, and listen in the capture phase so xterm doesn't swallow them. App shortcuts are always Ctrl+Shift+<key> (P palette, T new connection, W close tab, F SFTP, B sidebar, [ and ] switch tabs). Plain Ctrl+K, B and T belong to the shell (readline), so the app must not take them. Terminal clipboard (`XTermWrapper.tsx`): copy with Ctrl+Shift+C, Ctrl+Insert, or Ctrl+C while text is selected (otherwise Ctrl+C is SIGINT); paste with Ctrl+V, Ctrl+Shift+V or Shift+Insert; there is also a right-click menu. The handler calls `preventDefault`, because WebView2 would otherwise open the inspector on Ctrl+Shift+C and paste twice.
  - The SFTP panel (`components/sftp/SftpPanel.tsx`) handles keys only while it has focus: Total Commander-style F3/F5/F6/Shift+F6/F7/F8, arrows, Enter, Backspace, Space/Insert to select, Tab to switch panes, Ctrl+A, Ctrl+R. On Windows an empty local path means the drive list (`ListLocalDir("")`, `LocalParentDir`). Mouse selection is Explorer-style (click, Ctrl/Cmd+click toggle, Shift+click range; Shift+arrows extend). Rows drag between the panes (Shift on drop = move; dropping on a folder row targets that folder). Files from Explorer/Finder dropped on the server pane are uploaded: `main.go` enables Wails `DragAndDrop.EnableFileDrop`, and `lib/fileDrop.ts` registers the single `OnFileDrop` callback and dispatches by `data-file-drop` / `data-drop-dir` under the drop point.

- **Dragging server files out to Explorer** (`internal/dragout`, `connection/dragout.go`, `app_dragout.go`, `SftpPanel.remotePointerDrag`): server rows use a pointer-driven drag instead of HTML5 drag (an HTML5 drag belongs to the webview and can't carry files to another app). Over the Local pane a release is a download. When the pointer leaves the window with the button held, `SFTPStartDragOut` runs `DoDragDrop` on the window's own UI thread (the window is subclassed once and a private message runs the job; started from any other thread `DoDragDrop` never gets mouse input) with a hand-written COM data object (`FileGroupDescriptorW` + `FileContents` virtual files, no CGO); each file is an `IStream` reading from SFTP only when the target asks (a drop onto our own window is cancelled). `SFTPPrepareDragOut` lists the tree in the background as soon as the drag starts (cap `MaxDragItems`). Windows amd64/arm64 only; elsewhere the UI shows a toast. The COM objects are exercised by `dragout_windows_test.go`; the real drag into Explorer needs a manual check.
